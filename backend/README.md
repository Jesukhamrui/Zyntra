# Zyntra — Auth Backend

This backend provides authentication (signup, login, profile) for the Zyntra frontend.

## Quick start

1. Install dependencies

```powershell
cd backend
npm install
```

2. Create `.env` from the example and set a strong `JWT_SECRET`:

```powershell
copy .env.example .env
# then edit .env to set JWT_SECRET
```

3. Run in development (nodemon):

```powershell
npm run dev
```

4. Start for production:

```powershell
npm start
```

The server listens on `PORT` (default 4000) and exposes the API under `/api`.

## API Endpoints

### Health
- `GET /api/health` — Returns `{ ok: true, service: 'auth-backend' }`.

### Signup
- `POST /api/auth/signup`
- Body: `{ name, email, password }`.
- Validations: name/email/password required, password >= 6 chars, unique email.
- Success: 201 with `{ token, user }`.

### Login
- `POST /api/auth/login`
- Body: `{ email, password }`.
- Success: 200 with `{ token, user }`.

### Profile
- `GET /api/auth/me` — Requires `Authorization: Bearer <token>` header.
- Success: 200 with `{ user }`.

## Data storage

- Users are stored in `data/users.json` (created automatically on first run).
- Passwords are stored only as bcrypt hashes.

## Environment variables

- `PORT` — server port (default 4000)
- `JWT_SECRET` — secret key for signing JWTs (change in production)
- `CLIENT_ORIGIN` — allowed origin for CORS (default `http://localhost:5173`)

## Security notes

- Use a strong `JWT_SECRET` in production.
- Consider migrating to a real database for production (MongoDB/Postgres).
